# cMouse 无驱动方案可行性评估与技术路径决策

> 版本：1.0（2026-09-27）
> 结论先行：**"电脑端零安装、零驱动"在 Android 手机上完全可行；iPhone 因苹果平台限制无法做到零安装，
> 必须在电脑端运行一个极小的接收端程序（约 1–3 MB，无驱动、无内核组件）。全程任何路径都不需要内核驱动。**

---

## 1. 三条候选路径

### 路径 A：蓝牙 HID 设备直连（手机伪装成标准蓝牙键鼠）

手机 App 通过标准蓝牙 HID 协议把自己注册为"键盘 + 鼠标"复合设备，电脑像配对普通蓝牙鼠标一样配对手机，
使用操作系统内置的 HID 类驱动，**电脑端零安装、零驱动、零配置**。

| 平台 | 可行性 | 依据 |
|------|--------|------|
| Android 手机 | ✅ 可行 | Android 9（API 28）起提供公开 API `android.bluetooth.BluetoothHidDevice`，第三方 App 可注册为 HID 设备角色（SDP 自描述报告描述符），无需 root、无需系统权限 |
| iPhone | ❌ 不可行 | iOS 无任何公开的"HID 设备角色"API（CoreBluetooth 只提供客户端角色，即连接别人的 HID 设备，不能反过来扮演）。私有 API 无法通过 App Store 审核，也无法保证稳定性。**这是苹果的硬性平台限制，无法绕过** |

电脑端兼容性（路径 A）：

| 电脑系统 | 免驱识别 | 说明 |
|----------|----------|------|
| macOS 10.10+ | ✅ 内置 IOBluetoothHIDDriver | 配对后即出现在系统输入设备列表，即插即用 |
| Windows 8.1/10/11 | ✅ 内置 HID 类驱动栈 | 识别为标准蓝牙 HID 鼠标 + 键盘，各品牌电脑（含各厂商蓝牙芯片）行为一致 |

**必须如实告知的协议语义限制：**

标准 HID 鼠标/键盘描述符只能表达"相对位移、按键、滚轮、按键码"这类原子事件。
电脑端会把手机识别为**鼠标+键盘，而不是触控板**——这意味着：

- 无法触发 macOS 原生触控板引擎的私有多点手势（苹果 Magic Trackpad 协议未公开，逆向模拟极度脆弱且随系统更新失效，不做）；
- 无法把手机注册为 Windows Precision Touchpad（需注入专用 HID 数字化仪描述符 + 微软 WHQL 认证栈，Windows 对蓝牙虚拟精确式触控板的支持依赖系统版本，风险高，不做）。

**因此手势全部在手机端本地识别，翻译为标准鼠标/键盘语义**（详见 §3）。该方案下所有目标功能均可达成，
只是实现层级是"手机端智能手势 → 标准鼠标语义"，而非向系统注入原生多点触控事件。

### 路径 B：Wi-Fi 局域网 + 桌面接收端

手机 App 与电脑端接收端在同一局域网内通信（TCP，换行分隔 JSON，支持 Bonjour/mDNS 自动发现），
接收端用系统用户态 API 注入事件：

- macOS：`CGEventPost`（Quartz Event Services，用户态；仅需"辅助功能"授权，**不是驱动**）
- Windows：`SendInput`（Win32，用户态；无需管理员权限）

优点：iPhone 可用；可支持"绝对定位触控板模式"（屏幕映射，点哪指哪）、文本直传（虚拟键盘直接发整段文本，不经 HID 键值映射）、更高报告帧率。
缺点：**电脑端必须运行接收端程序**（macOS ~1 MB 单文件；Windows ~2 MB 单文件，.NET 8 AOT 自包含约 10 MB）。

### 路径 C：内核级虚拟设备驱动

（macOS 用 IOKit HID Event Driver / DriverKit，Windows 用 kmcl/vHID 驱动）
→ **直接否决**。需要签名、内核权限、系统更新易失效，与"安全、无侵入"的要求冲突。本项目任何路径都不包含内核组件。

## 2. 选定技术路径：A + B 双模混合

```
┌─────────────────────────── cMouse ───────────────────────────┐
│                                                              │
│  模式 A（Android 默认，零安装）：                              │
│    Android App ──蓝牙 HID（BR/EDR）──> 电脑内置 HID 驱动      │
│    电脑端：不装任何东西                                        │
│                                                              │
│  模式 B（iPhone 唯一路径 / Android 可选增强）：                │
│    Android / iOS App ──Wi-Fi TCP(JSON)──> cMouse Receiver    │
│    电脑端：运行一个菜单栏/托盘小程序（用户态事件注入，无驱动）    │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- **Android 用户**：默认模式 A，电脑端什么都不用装；想用绝对定位模式/更高保真时可选用模式 B。
- **iPhone 用户**：只能模式 B（平台限制，如实告知）；接收端是本项目唯一在电脑上安装的东西，
  体积以 KB–MB 计、无驱动、无后台云服务、数据全部本地 SQLite。
- **各品牌电脑兼容性**：两条路径都只依赖系统内置能力（HID 类驱动 / CGEventPost / SendInput），
  不依赖任何 OEM 专有接口，天然跨品牌（Intel/Apple Silicon/AMD/各厂商蓝牙模块）。

### 各平台实现差异总表

| 维度 | 模式 A（BT HID） | 模式 B（Wi-Fi 接收端） |
|------|------------------|------------------------|
| Android → macOS | ✅ 零安装 | ✅ 可选增强 |
| Android → Windows | ✅ 零安装 | ✅ 可选增强 |
| iPhone → macOS | ❌ 平台限制 | ✅ 唯一路径 |
| iPhone → Windows | ❌ 平台限制 | ✅ 唯一路径 |
| 电脑端安装 | 无 | 接收端（无驱动、单文件） |
| 光标/单击/双击/滚动 | ✅ | ✅ |
| 双指滚动（含水平） | ✅（滚轮 + AC Pan 报告） | ✅ |
| 双指捏合缩放 | ✅（翻译为 Ctrl+滚轮，绝大多数应用等效） | ✅（同左，或 Cmd/Ctrl+加减号） |
| 三指滑动自定义 | ✅（映射为可配置快捷键，如调度中心/任务视图） | ✅ |
| 虚拟键盘 | ✅（HID 键值映射） | ✅（Unicode 直传，支持中文整句输入） |
| 绝对定位模式 | ❌（HID 相对语义） | ✅ |
| 延迟 | 蓝牙典型 8–15 ms/报告 | 局域网典型 2–8 ms |
| 电脑端需授权 | 无 | macOS 需"辅助功能"授权（一次，系统设置内勾选） |

### 手机端系统版本要求

- 模式 A：Android 9.0+（`BluetoothHidDevice`）；Android 12+ 需运行时申请 `BLUETOOTH_CONNECT`/`BLUETOOTH_ADVERTISE`。
- 模式 B：Android 6.0+（minSdk 23，App 内按系统版本门控蓝牙模式）/ iOS 15+。
- 桌面接收端：macOS 11+（Universal 2，Intel/Apple Silicon）/ Windows 10+。

## 3. 手势语义映射表（手机端识别 → 标准事件）

| 手机端手势 | 模式 A 输出 | 模式 B 输出 |
|-----------|-------------|-------------|
| 单指滑动 | 鼠标相对位移报告 | 同左（或绝对定位） |
| 单指轻点 | 左键单击 | 同左 |
| 单指双击 | 左键双击（两次单击，间隔 < 系统双击阈值） | 同左 |
| 双指上下/左右滑动 | 垂直滚轮 / AC Pan 水平滚动报告 | 同左（带惯性曲线） |
| 双指轻点 | 右键单击 | 同左 |
| 双指捏合/张开 | Ctrl+滚轮（缩放） | Ctrl+滚轮 / Cmd+加减号 |
| 双指长按拖动 | 左键按住 + 位移（拖拽） | 同左 |
| 三指上/下滑 | 可配置快捷键（默认：macOS 调度中心 Ctrl+↑ / Windows 任务视图 Win+Tab） | 同左 |
| 三指左右滑 | 可配置快捷键（默认：全屏应用间切换 Ctrl+←/→） | 同左 |
| 键盘呼出 | HID 键盘报告（Shift/Ctrl/Cmd/Win 组合键支持） | Unicode 文本直传 |

## 4. 安全与数据

- **配对安全**：模式 A 走系统蓝牙配对（SSP，系统级安全）；模式 B 采用 6 位配对码（接收端首启生成并展示）+
  客户端白名单，仅监听局域网回环外的 TCP 8433 端口，拒绝未配对连接，无云服务、无外网依赖。
- **数据存储**：全部本地 SQLite——
  - Android：手势映射、灵敏度、主题、设备白名单（`cmouse.db`）；
  - 接收端：配对码、已授权设备、注入事件统计（macOS `~/Library/Application Support/cMouse/cmouse.db`；
    Windows `%APPDATA%\cMouse\cmouse.db`）。
- **隐私**：不采集任何数据，无网络上报。

## 5. 风险与如实告知清单

1. **iPhone 无法零安装**（苹果平台限制），电脑端需运行接收端；如无法接受，iPhone 支持无法实现。
2. 模式 A 下电脑把手机识别为键鼠而非触控板，系统触控板专属特性（如 macOS 用力点按、Windows 三指时间线 UI）
   不可用；等效功能以 §3 映射提供。
3. 部分安卓 OEM 对 `BluetoothHidDevice` 限制（极少见），App 内置"注册失败诊断"并在 UI 提示切换模式 B。
4. macOS 模式 B 首次使用需在"系统设置 → 隐私与安全性 → 辅助功能"勾选 cMouse（一次性，用户态授权，非驱动）。
5. 模式 A 的键盘输入受 HID 键值表限制，中文输入依赖电脑端输入法（与物理键盘行为一致）；整句直传请用模式 B。
